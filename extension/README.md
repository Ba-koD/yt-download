# yt-download 확장

유튜브 영상 페이지에 구간 편집 패널을 얹어, 고른 구간만 mp4 하나로 받습니다.
데스크톱 앱 없이 브라우저 안에서 전부 처리합니다.

## 설치

두 가지 길이 있습니다.

| | 북마클릿 | 확장 |
|---|---|---|
| 설치 | 버튼을 북마크 바로 끌어다 놓기 | 폴더를 풀고 개발자 모드로 얹기 |
| 갱신 | 누를 때마다 최신 | 새 zip 을 덮어쓰고 새로고침 |
| 쓸 때 | 탭마다 한 번 누르기 | 버튼이 늘 붙어 있음 |
| 서버 교대(리다이렉트) | 재시도로 버팀 | 예비 통로가 받아냄 |

받는 일 자체(구간 편집·화질 선택·라이브·이어받기)는 똑같습니다. **간단한 쪽을 원하면
북마클릿**, 늘 붙어 있는 버튼과 튼튼한 예비 통로를 원하면 확장입니다.

### 북마클릿 (설치 없음)

배포 페이지([`docs/index.html`](../docs/index.html), 깃허브 페이지로도 열립니다)에서
**구간 받기** 버튼을 북마크 바로 끌어다 놓으면 끝입니다. 유튜브 영상 페이지에서 그 북마크를
누르면 구간 편집 패널이 **떠 있는 창으로 바로 열립니다**(영상 오른쪽, 자리가 없으면 화면 아래.
제목 줄을 잡아 옮길 수 있습니다).

누를 때마다 배포처에서 최신판을 받아오므로 갱신할 일이 없습니다. 직접 올린 곳을 쓰려면
`python scripts/build-bookmarklet.py --base https://내가/올린/곳/` 으로 다시 만드세요.

### 확장

크롬 웹 스토어에는 올릴 수 없어(유튜브 약관) 직접 넣습니다. 브라우저가 스토어 밖 확장을
프로그램으로 넣는 길을 전부 막아둬서(정책·레지스트리·웹사이트 설치·개발자 도구를 하나씩
재봤다 — [`../CHANGELOG.md`](../CHANGELOG.md)) **처음 한 번은 사람이 손으로 얹어야 합니다.**

1. 릴리스에서 `yt-download-extension.zip` 을 받아 **계속 둘 폴더에 풀어둡니다**
   (개발자라면 이 저장소의 `extension` 폴더를 그대로 써도 됩니다. 어느 쪽이든 지우거나
   옮기면 확장이 사라집니다 — 확장은 이 폴더를 계속 참조합니다.)
2. `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 1번 폴더 고르기
4. 유튜브 영상 페이지를 열면 좋아요 줄에 **구간 받기** 버튼이 생깁니다

일반 영상(`/watch`)·라이브(`/live/`)·숏츠(`/shorts/`)에서 됩니다.
Chrome·Edge 에서 확인했고, Brave·Whale·Vivaldi·Opera 도 같은 방법으로 됩니다.

**프로필마다 한 번씩** 해야 합니다. 확장은 프로필마다 따로 저장되므로, 크롬에서 계정(프로필)을
여러 개 쓰면 그 프로필마다 3~4번을 되풀이해야 합니다.

**새 버전이 나오면**: 새 zip 을 받아 **같은 폴더에 덮어쓰고**, `chrome://extensions` 에서 이
확장의 새로고침(↻)을 한 번 누릅니다. 열려 있던 유튜브 탭은 F5 한 번 해주면 새 판이 붙습니다.

### 파이어폭스

배경 방식·확장 ID 가 달라 매니페스트를 바꾼 별도 빌드를 씁니다(릴리스에
`yt-download-extension-firefox.zip`, 또는 `python scripts/build-firefox.py`).
`about:debugging` → **임시 부가 기능 로드** → `dist/firefox/manifest.json`. 파이어폭스 128+ 필요.

파이어폭스 153 에서 일반 영상·숏츠 다운로드를 확인했습니다.
아직 확인 못 한 것: 비공개 영상, 진행 중 라이브.

### 사파리

`./scripts/build-safari.sh` — **macOS + Xcode 에서만** 됩니다. 처음 시험은 개발자용 메뉴의
"서명 없는 확장 허용", 배포는 Apple 서명·공증이 필요합니다. 아직 검증 못 했습니다.

## 쓰는 법

- `[` `]` (또는 `I` `O`) — 지금 재생 위치를 시작·끝으로 찍기
- `⇤` `⇥` (또는 `Home` `End`) — 시작점을 맨 앞, 끝점을 맨 끝으로(끝에 두면 "끝까지")
- 타임라인 손잡이로 구간 잡기 — 영상은 **손을 놓을 때** 그 지점으로 갑니다
- 화질을 고르고 **구간 받기** → mp4 로 저장. 받는 동안 일시정지·정지 버튼이 나옵니다
- 고른 구간은 영상별로 기억했다가 다시 열면 되살립니다

**파일은 고른 구간보다 앞뒤로 몇 초 길 수 있습니다.** 영상은 키프레임(조각 경계)에서만
자를 수 있는데, 그 부분을 잘라내려면 재인코딩이 필요해서 하지 않습니다(무손실이 이 확장의
핵심입니다). 소리는 영상 트랙과 **같은 지점에서 시작하고 끝나도록** 실제로 잘라 맞추므로
어긋나지 않습니다. 파일 이름과 완료 메시지("앞 2.0초·뒤 1.3초가 더 붙었습니다")가
실제 시작·끝 지점을 알려줍니다.

## 어떻게 동작하나

```
InnerTube(ANDROID_VR)에 물어보기 → 포맷별 직접 주소
   ↓  색인(sidx) 2KB 만 받아 "시간 → 바이트" 계산
구간에 걸치는 조각만 Range 로 받기 → 샘플 표를 지어 일반 mp4 하나로 담기(재인코딩 없음)
```

**자르는 방식.** 영상은 조각 맨 앞의 키프레임에서만 시작할 수 있어서, 고른 지점보다 앞선
조각 경계부터 파일이 시작합니다. 그 앞부분을 잘라내면 남은 프레임이 참조할 그림이 사라져
화면이 안 나옵니다. 그래서 **앞은 잘라내지 않고 편집 목록(elst)으로 가리고, 뒤는 샘플
단위로 실제로 잘라냅니다.** 편집 목록은 조각 mp4 에서는 무시되므로 샘플 표(stbl)를 갖춘
일반 mp4 로 담습니다. 바이트는 옮겨 담을 뿐이라 다시 인코딩하는 곳은 없습니다.

요청 통로가 종류마다 다릅니다. content script 는 youtube.com 오리진에서 돌아
InnerTube 를 동일 출처로 부르고, 미디어(googlevideo)는 교차 출처라 페이지(MAIN) 쪽
`page-fetch.js` 가 대신 받아옵니다. 배경 일꾼으로 보내면 `Origin` 이 붙어 403 이 납니다.

깊은 사정(로그인 영상의 `n` 해제, 소리 정렬, 라이브 시간축, 파이어폭스 realm 문제 등)은
[`../HANDOFF.md`](../HANDOFF.md) 에 직접 재서 확인한 값으로 정리해 뒀습니다.

## 지금 한계

| | 상태 |
|---|---|
| mp4 화질(H.264 · AV1 4K) | 됨 |
| webm(VP9) | 안 됨(색인 방식이 다름) |
| 진행 중인 라이브 | 됨(조각 번호 `&sq=N` 로 받음) |
| 비공개·멤버 전용 | 됨(로그인 브라우저에서. `SAPISIDHASH` + `n` 해제 필요) |
| 자르는 정확도 | 고른 그대로. 실측 오차 0.00ms, 원본과 픽셀 단위로 같음, 소리 어긋남 0.000ms |
| 프레임 단위 | 영상은 프레임 단위로만 존재해서, 고른 지점을 담고 있는 장부터 시작함(30fps 면 최대 33ms) |
| 저장 방식 | 조각을 OPFS 에 쌓아 이어받기가 됨. 메모리에는 한 번에 조각 하나만 |
| 받을 수 있는 구간 | 로그인하면 **영상 전체**. 로그아웃이면 앞 60초까지(아래) |

### 받을 수 있는 구간 — 로그인하면 전체, 아니면 앞 60초

유튜브는 2026-08-02 부터 **PO 토큰(Proof of Origin)** 없이는 영상 **앞부분 약 60초까지만**
내어줍니다. 그 너머는 언제나 `HTTP 403` 입니다
([yt-dlp #17348](https://github.com/yt-dlp/yt-dlp/issues/17348)).

몫이 아니라 **위치 제한**입니다. 아무것도 받지 않은 새 주소로 곧바로 뒷부분을 달라고 해도
403 이고, 기다려도 열리지 않습니다. 직접 잰 값:

| 영상 | itag | 경계 | 시간 |
|---|---|---|---|
| 634초 4K | 299 | 23.27MB (9.5%) | 60초 |
| 634초 4K | 160 (144p) | 0.48MB (11.7%) | 74초 |
| 112초 | 299 | 20.8MB (53.6%) | 60초 |

바이트가 아니라 시간 기준이라 화질을 낮춰도 더 뒤로 못 갑니다.
`ANDROID_VR`·`IOS`·`ANDROID` 세 클라이언트의 경계가 바이트까지 같아서 갈아타도 못 넘고,
`begin=`·`range=`·`ratebypass=`·`alr=` 같은 매개변수로도 옮길 수 없습니다.

**로그인하면 이 벽이 사라집니다.** 우리는 유튜브 페이지 **안에서** 도니까, 페이지가 들고 있는
토큰 발급기(WebPoClient)를 그대로 불러 PO 토큰을 만들 수 있습니다. yt-dlp 같은 바깥 도구가
이걸 쓰려면 브라우저를 따로 띄워야 하는데, 우리는 이미 그 안입니다.

로그인 상태에서 하는 일:

1. `WEB_CREATOR` 로 내 계정으로 물어 주소를 받고
2. 주소에 붙은 `n` 을 풀고(`nsig.js`)
3. 페이지의 발급기로 GVS PO 토큰을 만들어 `&pot=` 로 붙입니다
   (로그인 시 계정에, 아니면 방문자에 묶습니다 — yt-dlp 와 같은 규칙)

실측: 634초 영상에서 `08:00~08:05`, `10:25~10:34`(맨 끝) 모두 정확히 받혔습니다.
`contentLength`·`initRange`·`indexRange` 가 `ANDROID_VR` 것과 같아서 색인·이어받기도 그대로입니다.

**로그아웃 상태는 아직 앞 60초까지입니다.** 웹 계열 클라이언트가 이제 평범한 주소를 주지 않고
SABR 만 주기 때문입니다. 그쪽을 뚫으려면 SABR 을 구현해야 합니다
([`../HANDOFF.md`](../HANDOFF.md) 의 "남은 숙제" 참고).
