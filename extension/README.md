# yt-download 확장 (실험 중)

유튜브 영상 페이지에 구간 편집 패널을 얹어, 고른 구간만 mp4 하나로 받습니다.
데스크톱 앱 없이 브라우저 안에서 전부 처리합니다.

## 설치

Chrome 웹 스토어에는 올릴 수 없습니다(유튜브 이용약관이 다운로드를 금지합니다).
직접 로드해서 씁니다.

1. `chrome://extensions` 를 엽니다
2. 오른쪽 위 **개발자 모드**를 켭니다
3. **압축해제된 확장 프로그램을 로드**를 누르고 이 `extension` 폴더를 고릅니다
4. 유튜브 영상 페이지를 열면 오른쪽 아래에 패널이 나타납니다

일반 영상(`/watch`), 라이브(`/live/`), 숏츠(`/shorts/`)에서 됩니다.
Chrome 과 Edge 에서 확인했습니다. Brave·Whale·Vivaldi·Opera 도 같은 계열이라 같은 방법으로 됩니다.

**갱신은 저절로 됩니다.** 관리자가 폴더를 갈아 끼우면 확장이 그걸 알아채고 스스로 다시 켜며,
열려 있던 유튜브 탭에도 새 판을 넣습니다. `chrome://extensions` 새로고침도 F5 도 필요 없습니다
(스스로 갈아타지 못하는 자리라면 패널이 그렇다고 알려줍니다).

### 파이어폭스 (실험 · 검증 전)

파이어폭스는 확장 구조가 조금 달라(배경이 service_worker 가 아니라 이벤트 페이지, 확장 ID 를
못박아야 함) 매니페스트를 바꿔 담은 별도 빌드를 씁니다.

```bash
python scripts/build-firefox.py     # dist/firefox/ 와 dist/yt-download-extension-firefox.zip
```

`about:debugging` → **이 Firefox** → **임시 부가 기능 로드** → `dist/firefox/manifest.json` 을 고릅니다.
(임시 로드는 파이어폭스를 껐다 켜면 사라집니다. 영구 설치는 서명(AMO)이 필요합니다.)

파이어폭스 **128 이상**이 필요합니다(`world: "MAIN"` 이 그때부터 됩니다).
아직 실제로 얹어 확인하지 못했습니다 — 확인할 곳:

- 좋아요 줄에 **구간 받기** 버튼이 붙는지
- 화질 목록이 뜨는지(안 뜨면 배경 이벤트 페이지나 `world: "MAIN"` 문제)
- 실제로 받아지는지(막히면 `declarativeNetRequest` 대신 배경 예비 통로로 넘어갔는지 콘솔 확인)

### 사파리 (macOS·Xcode 필요)

사파리 확장은 웹 확장을 감싼 맥 앱으로만 배포되고, 그 변환·서명·빌드를 애플 도구가 합니다.
**윈도우·리눅스에서는 만들 수 없습니다.** macOS + Xcode 에서:

```bash
./scripts/build-safari.sh           # extension/ → Xcode 프로젝트 → 맥 앱
```

처음 시험은 사파리 개발자용 메뉴에서 **"서명 없는 확장 프로그램 허용"** 을 켜야 하고
(사파리를 새로 켤 때마다 다시 켜야 합니다), 남에게 배포하려면 Apple Developer 서명·공증이 필요합니다.
사파리는 확장이 서명된 앱 번들 안에 들어가서 **"폴더만 갈아 끼우는" 자동 갱신이 안 됩니다** —
갱신하려면 앱을 다시 빌드·서명해야 합니다.

## 쓰는 법

- **현재 위치 IN / OUT** — 재생 중인 지점을 시작/끝으로 잡습니다
- `[` `]` 버튼이나 `I` `O` 키로 지금 위치를 시작·끝으로 찍습니다
- `⇤` `⇥` 버튼이나 `Home` `End` 키로 시작점을 맨 앞, 끝점을 맨 끝으로 보냅니다
  (끝점을 맨 끝에 두면 "끝까지"로 잡혀서, 라이브는 방송이 나아가는 만큼 따라갑니다)
- 타임라인 손잡이를 끌어 구간을 잡습니다. 영상은 **손을 놓을 때** 그 지점으로 갑니다
  (끄는 내내 따라가면 되감기가 이어져 화면이 어지럽습니다). 재생 위치 막대는 끄는 즉시 따라갑니다
- 고른 구간은 영상별로 기억해뒀다가 다시 열면 되살립니다
- 화질을 고르고 **구간 받기**를 누르면 mp4 파일로 저장됩니다
- 받는 동안 **일시정지 / 정지** 버튼이 나타납니다. 일시정지는 이미 나간 요청만 끝내고
  다음 조각부터 멈춥니다(길어야 몇 초)

## 어떻게 동작하나

```
페이지에서 VISITOR_DATA 읽기
   ↓
InnerTube(ANDROID_VR 클라이언트)에 물어보기 → 포맷별 직접 주소
   ↓
색인(sidx) 2KB 만 받아서 "시간 → 바이트" 표 만들기
   ↓
고른 구간에 걸치는 조각만 Range 로 받기 (동시 6개)
   ↓
영상·소리 트랙을 mp4 하나로 엮기 (재인코딩 없음)
```

요청은 종류에 따라 통로가 다릅니다. 여기가 제일 손대기 쉬운데 제일 잘 깨지는 곳입니다.

| 대상 | 어디서 | 왜 |
|---|---|---|
| youtube.com (InnerTube) | content script | 동일 출처라 그냥 됩니다 |
| googlevideo (미디어) | 페이지(MAIN) 쪽 `page-fetch.js` | content script 에서 부르면 교차 출처로 막힙니다 |

배경 일꾼(service worker)으로 보내면 안 됩니다. 두 가지가 함께 터집니다.

- 요청에 `Origin: chrome-extension://…` 이 붙는데 InnerTube 는 그런 요청에 **403** 을 줍니다.
- `chrome.runtime.sendMessage` 는 JSON 직렬화라 **ArrayBuffer 가 빈 객체로 사라집니다**
  (받은 바이트가 0이 되어 `sidx 박스를 찾지 못했습니다` 로 끝납니다).

페이지 안에서 부르면 유튜브 자신이 부르는 것과 같아 둘 다 통과하고,
`postMessage` 는 구조화 복제라 바이트가 그대로 넘어옵니다.

### 로그인이 필요한 영상

`ANDROID_VR` 은 로그인 정보를 아예 받아주지 않아서 내 비공개 영상은 `Please sign in` 으로 끝납니다.
창작자용 클라이언트(`WEB_CREATOR`)로 다시 물어보는데, **쿠키만 보내면 여전히 거절당합니다.**

```
WEB_CREATOR / 쿠키만        -> LOGIN_REQUIRED, 포맷 0
WEB_CREATOR / 쿠키+인증헤더 -> OK, 포맷 7
```

유튜브 웹 화면과 같은 방식으로 `SAPISID` 쿠키와 지금 시각을 SHA-1 로 해시해
`Authorization: SAPISIDHASH <시각>_<해시>` 를 붙여야 로그인으로 인정됩니다.
`SAPISID` 는 HttpOnly 가 아니라 `document.cookie` 로 읽을 수 있습니다.

**여기서 끝이 아닙니다.** 인증이 통해도 그 주소로는 바이트가 오지 않습니다.

```
올바른 n  -> HTTP 206
뒤집은 n  -> HTTP 403
n 제거    -> HTTP 403
```

웹 계열 클라이언트가 주는 주소에는 속도 제한용 `n` 이 붙고, 풀지 않으면 403 입니다.
푸는 일은 `src/nsig.js` 가 시키고, 실제 계산은 `src/page-fetch.js` 가 페이지 쪽에서 합니다.
해결기는 코드를 만들어 돌리는데, 확장 안에서는 그게 금지돼 있고 유튜브 페이지는
CSP 가 `unsafe-eval` 을 허용해서 거기서는 됩니다.

계산은 **빈 iframe 안에서** 합니다. 여기서 두 번 넘어졌습니다.

- 유튜브는 본 화면의 내장 함수를 자기 것으로 바꿔치기해 뒀습니다.
  그대로 돌리면 파서가 엉뚱한 데서 터집니다(`... 'attestationRequest' in null`).
- 해결기가 준비 과정에서 `globalThis.location` 에 값을 넣습니다.
  창에서는 그게 곧 페이지 이동이라 유튜브가 날아갑니다.

새로 만든 iframe 은 손타지 않은 깨끗한 곳이고, 떠나도 본 화면은 멀쩡합니다.
푸는 일은 동기라 답을 받은 뒤에 이동이 일어나므로, 받자마자 틀을 치웁니다.
`blob:` 일꾼은 못 씁니다 — 유튜브 CSP 의 `script-src` 에 `blob:` 이 없습니다.

로그인을 받아주면서 `n` 이 없는 클라이언트는 없습니다. 직접 다 재봤습니다.

| 클라이언트 | 쿠키만 | 쿠키+인증 |
|---|---|---|
| IOS / ANDROID / ANDROID_VR | `LOGIN_REQUIRED` | HTTP 400 |
| WEB_CREATOR / TVHTML5 | `LOGIN_REQUIRED` | 주소 나옴(단 `n` 붙음) |

### 숏츠

받는 일은 일반 영상과 똑같습니다(같은 영상 ID, 같은 InnerTube 응답). 화면만 다릅니다.
실제로 붙여보고 알아낸 것들입니다.

| | 숏츠에서는 |
|---|---|
| 버튼 자리 | `reel-action-bar-view-model` (좋아요·댓글이 있는 오른쪽 세로 줄). 일반 화면의 `#actions` 는 숏츠에도 **빈 껍데기로 남아 있어서** 그걸 찾으면 크기 0인 자리에 버튼을 붙이게 됩니다 |
| 버튼 크기 | 48px 동그라미 + 그 아래 글자 = 78px, 여백 0. 그 줄은 `gap` 도 `margin` 도 없이 **칸 높이로만** 간격을 만듭니다. 여백을 따로 주면 우리 것만 어긋납니다 |
| 지금 보는 편 | `ytd-reel-video-renderer` 는 **하나뿐**이고 유튜브가 그 안을 갈아 끼웁니다. `is-active` 같은 표시는 없습니다. 플레이어(`#shorts-player`)가 들어 있는 쪽을 지금 보는 편으로 봅니다 |
| 플레이어 | `#shorts-player`. 그런데 `#movie_player` **도 함께 있고**, 그건 값이 전부 0 인 빈 껍데기입니다. 하나만 골라 보고 끝내면 길이를 0 으로 읽습니다 |
| 패널 | 끼워 넣을 자리가 없어 띄웁니다. 세로 버튼 줄 오른쪽 빈자리에 세우되, 자리를 **재서** 넣습니다(고정값은 그 버튼들을 덮습니다). 제목 줄을 잡아 옮길 수 있고, 좁으면 화면 아래에 눕습니다 |

가운데 모달로 띄우지 않는 이유: 손잡이를 놓으면 유튜브 영상이 그 지점으로 가서
화면 자체가 미리보기입니다. 영상을 가리면 그 미리보기를 잃습니다.

### 리다이렉트와 CORS

googlevideo 는 가끔 다른 호스트로 넘깁니다(`cms_redirect`). 그런데 **넘어간 쪽 응답에는
`Access-Control-Allow-Origin` 이 없어서** 브라우저가 막아버립니다. 간헐적이라 더 헷갈립니다.

그래서 두 겹으로 막습니다.

1. `src/rules.json` 으로 googlevideo 응답에 그 헤더를 붙입니다
   (`declarativeNetRequest` 의 `modifyHeaders`).
   **주의**: 이 규칙이 먹으려면 요청 대상(`*.googlevideo.com`)뿐 아니라
   **요청을 시작한 쪽(`www.youtube.com`)에도 host 권한**이 있어야 합니다.
   하나라도 빠지면 규칙이 조용히 무시됩니다.
2. 그래도 막히면 배경 일꾼이 대신 받아옵니다. `sendMessage` 는 JSON 직렬화라
   바이트를 base64 로 바꿔 넘깁니다. 느리지만 리다이렉트를 타도 막히지 않습니다.

웹 클라이언트로 물어보면 유튜브가 주소를 주지 않습니다(SABR 로 넘어갔습니다).
`ANDROID_VR` 클라이언트는 아직 주소를 그대로 주고, 속도 제한용 `n` 파라미터도 붙지 않아
서명 해독이 필요 없습니다. **여기가 가장 먼저 깨질 곳입니다** —
받아지지 않으면 `src/innertube.js` 의 `CLIENT` 를 먼저 의심하세요.

### 소리는 영상이 시작하는 지점부터 받아야 합니다

영상과 소리는 조각이 끊기는 지점이 다릅니다(예: 영상 24.6초 / 소리 29.95초).
고른 지점이 그 사이에 있으면 **소리 조각이 영상 조각보다 늦게 시작합니다.**
그 상태로 두 트랙을 나란히 0초에 붙이면 소리가 그만큼 앞서 갑니다.

```
고치기 전:  소리 원본 29.96초 / 화면 원본 24.50초  -> 어긋남 5.46초
고친 뒤:    소리 원본 24.60초 / 화면 원본 24.50초  -> 어긋남 0.10초
```

그래서 소리는 **영상 조각이 시작하는 지점부터** 받고, 앞의 남는 부분을 실제로 잘라냅니다.
잘렸는지는 파일에서 바로 확인할 수 있습니다 — 소리 첫 조각이 통짜(430 표본)면 안 잘린 것입니다.

### 앞부분을 편집 목록으로 건너뛰면 안 됩니다

영상은 키프레임에서만 자를 수 있어서, 고른 지점보다 몇 초 앞에서 시작합니다.
그 앞부분을 편집 목록(`elst`)으로 "건너뛰라"고 적어두면 될 것 같지만, **안 됩니다.**

재생기는 그 지시를 **소리에만** 적용합니다. 영상은 앞 프레임들이 디코딩에 필요해서
그대로 두고 음수 시각을 붙입니다. 그래서 소리만 앞으로 당겨져 어긋납니다.

실제로 잰 값입니다.

```
고치기 전:  소리 밀림 4.96초 / 화면 밀림 0.00초  -> 어긋남 4.96초
고친 뒤:    소리 밀림 0.00초 / 화면 밀림 0.00초  -> 어긋남 0.00초
```

원본과 대조해도 소리 36.16초, 화면 36.25초 지점으로 같은 곳을 가리킵니다.

그래서 앞은 건드리지 않고 뒤 길이만 맞춥니다. 대신 파일 이름을 실제 시작에 맞춰 붙이고,
몇 초가 더 붙었는지 상태줄에 적습니다.

## 지금 한계

| | 상태 |
|---|---|
| mp4 화질 (H.264 / AV1) | 됨. 4K 포함 |
| webm 화질 (VP9) | 안 됨 — 색인 방식이 달라 아직 못 읽습니다 |
| 진행 중인 라이브 | 됨 — 색인이 없어 조각 번호(`&sq=N`)로 하나씩 받습니다 |
| 처리 중인 지난 라이브 | 방송이 끝나고 유튜브가 다시보기를 만드는 동안에는 화질이 제한될 수 있습니다 |
| 자르는 정확도 | 앞에 몇 초가 더 붙습니다(영상은 키프레임에서만 잘립니다). 파일 이름은 실제 시작에 맞춰 붙고, 소리와 화면은 어긋나지 않습니다 |
| 내 비공개·멤버 전용 영상 | 로그인한 브라우저라면 됩니다. 쿠키만으로는 안 되고 `SAPISIDHASH` 인증 헤더가 필요합니다(아래 참고) |
| 연령 제한 영상 | 확인하지 못했습니다 |
| 저장 방식 | 통째로 메모리에 담았다가 저장합니다. 아주 긴 구간은 무리입니다 |

4K 는 AV1(mp4)로 받습니다. VP9(webm)만 있는 영상은 목록에 나오지 않습니다.
